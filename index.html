Featured · TSF

TSF Mobile B2B

Mobile B2B activity has to become a fulfillment request, and the result has to land back on the order. I worked the request path of that chain.

  • What it is. A Kafka-backed fulfillment flow. An activity event is mapped and validated into one shared envelope, handed off asynchronously so the outside work sits off the order path, then the outcome is written back to service order management.
  • What I did. The request side: take the activity, shape the envelope, and publish it on. Adapters share one library, so a new event extends the chain instead of starting a new design. A bad payload is held aside so it does not stall the rest.
  • Stack. Java, Apache Camel K, Spring Boot, Kafka, Kubernetes.

Featured · TMF-622

Product order orchestration

TMF-622 is the TM Forum product-order standard. These services take an order for a telecom product and carry it through fulfillment.

  • What it is. Eight or more event-driven microservices for NBN, Fiber, and Digital SIM. The live flow carries 50K+ orders a day.
  • What I did. Built those services, then tuned Kafka consumers and PostgreSQL queries. Under 3K+ concurrent SVT transactions, fulfillment latency dropped about 20%.
  • Stack. Java, Spring Boot, Kafka, PostgreSQL, TMF-622.
